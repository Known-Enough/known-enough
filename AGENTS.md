The user explicitly requested this check for future pushes. Main is the active integration branch; see [docs/main-integration.md](docs/main-integration.md) for included work and synchronization instructions. All tasks belong to one shared pool. Preserve existing active claims until explicitly released. Record the claimant and bounded file scope before work; coordinate overlapping files, contracts, root config, lockfile and CI. Independent critical review and human acceptance remain required. Follow the workflow for safe claims and transfers. No cross-account agents or access to another user's credentials.

Never import server fixtures or backend code into the browser. Public snapshots are strict allowlists, never private object spreads. No real personal data, secrets, private conditions, grant IDs or refusal details in public payloads/logs. Verified server identity determines the owner; mock identities are not authentication.

Exception, disclosure and final acceptance are independent permissions. Semantic revisions supersede old consent; control versions guard concurrent changes. A public plan hash contains only public facts and an opaque context token. Hash/schema checks are not authorization or transaction enforcement.

Use pinned Node/npm. Run focused checks during work and npm run check before an implementation handoff or integration checkpoint (install Playwright Chromium first; documented Chrome fallback is allowed). For documentation-only work, verify links, task consistency and reference hashes; no application suite is required unless executable files changed. Record actual evidence. No solver/application behavior in F00–F02.

Maintain the task's status, your own docs/work-log-A.md or docs/work-log-B.md, and a concise handoff. Critical checkpoints inspect code and tests as well as logs; changed reviewed code needs follow-up review. Preparation against mocks does not satisfy live acceptance. Leave implemented tasks REVIEW until human review/integration; reported completion elsewhere is not local verification.

Do not publish, push, open PRs, merge, deploy, create paid resources or spend money without explicit user authorization. No automatic external messages. See the workflow for safe transfer and checkpoint rules.
