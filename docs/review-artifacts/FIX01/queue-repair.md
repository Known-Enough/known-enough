# FIX01 queue lifecycle repair

Public draft requests could occupy both global slots after an unconfirmed call, while a new pre-call request expired but was still labeled PENDING. A failed follow-up also discarded the browser draft on closing its request. The repair distinguishes pre-call/expired/running/uncertain statuses, preserves the saved draft and answer on closing, rejects unavailable capacity before enqueue, and releases unused/rejected provider attempts while preserving charged reservations. Public calls have an18-second bounded response window and25-second lease with27-second draft-only I/O; private defaults remain unchanged. Genuine unconfirmed calls are not replayed or freed by a timeout. Failure logs expose only dispatch/acknowledgement flags and phase/reason.

Recovery is separate from retrying the model: fixed-account/function/model CloudTrail completion receipts must cover the exact token/cost reservation delta from the verified disabled-empty [baseline38521196882](https://github.com/Known-Enough/known-enough/actions/runs/38521196882). The existing API legacy model flags must still be disabled and its independently checked code hash must match. All counted calls use one SDK attempt and the same durable public reservation. The proof does not guess an individual call from a nearby timestamp. It preserves all reservations/unknown usage, private backups and original job references, and conditionally retires only expired public jobs before disabling/emptying the control. A private immutable S3 backup must read back before the single transaction. There are no participant, draft or TOTAL writes, no provider invocation and no IAM change.

AWS documents `Converse` as a CloudTrail management event and `eventTime` as the completion time: [Bedrock CloudTrail](https://docs.aws.amazon.com/bedrock/latest/userguide/logging-using-cloudtrail.html), [CloudTrail record fields](https://docs.aws.amazon.com/awscloudtrail/latest/userguide/cloudtrail-event-reference-record-contents.html). Missing, truncated, duplicated or nonmatching receipts stop recovery. Installed lookup access and actual coverage are not inferred from project authorization.
