The `authorization` object is an explicit initial recurring envelope, disabled in the example. All fields are required: `approved`, UTC `expiresAt`, `maxRunsPerDay`, `maxAttemptsPerRun`, `maxTokensPerRun`, `maxCostMicrosPerRun`, `attemptCostMicros`, `maxSignupMessagesPerRun`, `maxSignupMessagesPerDay`, `retentionReviewed` and `invocationLoggingDisabled`. One micro is USD 0.000001. Zero/unapproved/expired envelopes cannot provision fixtures, deliver verification messages or invoke a model. Apply itself requires the approved resource/publication scope as well as the concrete envelope; editing an example does not grant that permission.

A possible review envelope, **not approved**, is two runs/day for seven days, 200 attempts/run, 250,000 conservatively reserved tokens/run, USD 0.25/run, minimum reservation 1 micro/attempt, two signup messages/run and four/day. The server reserves the larger of the minimum and one micro per input-byte-plus-output-token before every provider attempt, with CAS protection, no refund after failure and SDK retries disabled. At these limits, model reservation is at most USD 0.50/day and USD 3.50 over seven days. Public/private model prompts both use the real application/provider; no scripted provider is bundled. The daily run ceiling also bounds total attempts/tokens. Attempts denied by contention consume no provider call. Approved installation must verify that regional standard Nova Lite pricing remains below the conservative USD 1/million token ceiling. [AWS Bedrock pricing](https://aws.amazon.com/bedrock/pricing/).

Verification recipients are exactly the current run's synthetic signup address under the controlled domain. Precreated login accounts are created with suppressed messaging. The Cognito custom-message trigger counts signup/resend messages transactionally before sending and rejects all other sends. Real signup uses the real code placeholder and SES delivery, not admin confirmation. [Cognito custom-message behavior](https://docs.aws.amazon.com/cognito/latest/developerguide/user-pool-lambda-custom-message.html).

## Where to click and the one entry command

The account's installed CloudShell AWS session supplies only this one-time setup authority.

Run this command, replacing `PACKAGE_COMMIT` with the exact 40-character release commit. Start with `dry-run`, then `validate`, then use the same command with the authorized `apply` mode:

```bash
COMMIT=PACKAGE_COMMIT; curl --fail --silent --show-error "https://raw.githubusercontent.com/Known-Enough/known-enough/$COMMIT/scripts/live-qa/setup.sh" -o /tmp/known-enough-qa-setup.sh && bash /tmp/known-enough-qa-setup.sh "$COMMIT" dry-run "$HOME/live-qa-config.json"
```

The pinned script clones/checks out that exact commit, checks the Node distribution checksum, installs Node 24.21.0/npm 11.19.0 and both exact locks, and builds deterministic ZIPs without server test fixtures. It never executes a branch-selected package. `dry-run` does no AWS call; `validate` performs account, ownership and mail conflict reads without writes. `apply` creates/updates the reviewed resources, verifies SES, publishes QA web/backend artifacts, installs the envelope and performs configuration/hash readback. `readback` repeats configuration/hash checks without invoking users or models. Successful setup prints `SETUP_READBACK_PASS` with `cloudQualification=PENDING_LIVE04`; this is not a passing journey. If the repository is not anonymously accessible, LIVE04 must provide an approved package distribution method before running this command; do not share personal GitHub tokens.

The script keeps package files and any full primary rollback snapshots under private directory `/tmp/known-enough-live-qa-COMMIT/package`. Preserve that directory privately through installation/rollback; CloudShell temporary files may not survive session replacement. Upload its **allowlisted** `installed-target.json` and reviewed artifact receipt for the LIVE03 installation configuration. It includes identifiers/hashes but no login passwords, email addresses, group HMAC key or Lambda environment. LIVE03 defines publication of this target independently of test reports.

## Exact resources and target differences

Two CloudFormation stacks (`known-enough-live-qa-mail`, `known-enough-live-qa`) own a separate Amplify app/main branch, HTTP API/JWT authorizer, Cognito pool/two public code-flow clients/domain, four Lambda functions, three on-demand encrypted DynamoDB tables, seven-day Lambda log groups, synthetic-login secret, exact OIDC test/release roles, SES identity/receipt rule set, private mailbox bucket with one-day expiry, and reviewed subdomain MX/DKIM records. A separate tagged private S3 bucket stores content-addressed release ZIPs. No NAT, provisioned model throughput or real participant account is created. [SES identity/DKIM outputs](https://docs.aws.amazon.com/AWSCloudFormation/latest/TemplateReference/aws-resource-ses-emailidentity.html).

Primary/QA run the same `api.zip` executable with different exports: primary `api.handler` is the existing production handler; QA `api.qaHandler` adds an active lease and server-side model budget around that application. QA broker is not a public route. Browser source is the same, compiled with explicitly different API/pool/client/hosting identifiers. QA uses isolated group **and** decision tables. The primary rollout retains the existing decision table, identity pool, clients, domain, integration and authorizer; creates/reuses a compatible encrypted group table; adds only the reviewed group/draft routes and group item policy; preserves the full supported Cognito settings and Lambda environment; and leaves primary models disabled. QA model success cannot be claimed as primary model availability. Primary frontend release and live comparison are separate LIVE03/LIVE04 evidence. When primaryRollout is explicitly enabled, the prepared stack also installs KnownEnoughGithubPrimaryRelease: code-only update/readback on known-enough-stage-api, GetObject on verified release artifacts and AUTH/LEASE reads. It cannot change environment, IAM, Cognito or data. LIVE03 uses that separate workload job for later approved backend releases without A credentials; model-off/revision/envelope guards remain required.

The OIDC test role can invoke only the fixture broker, read only synthetic login secrets and collect the QA API configuration/logs. It cannot create arbitrary accounts, mutate data directly, deploy, invoke Bedrock or read personal credentials. The release role can change code on the four QA functions, publish only QA main and access only its artifact bucket; it cannot change environment/IAM/Cognito. Exact immutable GitHub main subject is required. The broker validates the run manifest before account operations and before deleting exact decision keys; foreign aggregate data or incomplete cleanup blocks further runs.

## Recovery and rollback

A failure prints a static code and leaves private state available for diagnosis; it never dumps AWS diagnostics, passwords or environment values. Retry `apply` with the same pinned source/configuration/private directory after a transient failure. CloudFormation preserves the group hash key on update. A failed stack or conflicting/drifted resource requires reviewed forward repair; the installer refuses to import or reset it silently. `readback` validates repaired output. Budget updates are blocked during a run; finish that run's exact cleanup first.

Use the same entry command with `rollback` to revoke installed recurring authorization and remove the two exact GitHub role policies. Resources/data are retained for forward repair. If installed, revoke the distinct primary backend release policy as well before considering recurring publication disabled. It refuses incomplete cleanup and does not reset tables or delete unrelated mail routing. For an optional primary rollout it restores the verified prior ZIP, full environment/handler and supported pool/client settings, deletes only newly recorded route IDs/policy, and retains the group table. Lambda revision and Cognito snapshot drift block rollback before overwriting concurrent work. Keep the private primary journal and ZIP: missing snapshots cannot be reconstructed from a sanitized report. Reapply the reviewed template to restore revoked role policies only after authorization. LIVE04 must prove retry/cleanup/rollback behavior against actual services; local simulation cannot establish installed IAM, SES delivery or CloudFormation validity.

This is not a billing cap or a claim of free-tier eligibility. One Secrets Manager secret has a USD 0.40/month storage charge plus API calls. Hosting storage/transfer, S3 objects/requests, seven-day logs, Lambda/API calls, DynamoDB reads/writes, Cognito active users, DNS queries and SES delivery/receipt are usage billed. Reuse the approved existing hosted zone rather than purchase a domain here. Dedicated verification-mail storage expires after one day. [Secrets Manager pricing](https://aws.amazon.com/secrets-manager/pricing/), [Amplify pricing](https://aws.amazon.com/amplify/pricing/), [SES pricing](https://aws.amazon.com/ses/pricing/).
