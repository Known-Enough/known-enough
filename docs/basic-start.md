# Start a shared decision

Choose **Create account**, enter a username, email and a password matching the displayed policy, then verify the email code. Use **Sign in** after verification. Cancel account creation clears entered details; a request with an uncertain result should use the displayed recovery step rather than repeated submission.

Request account access. Account approval and group membership are separate. Once approved, create a group or accept the intended recipient's invitation. Accepting an invitation does not approve a decision. Group members and membership actions are under **Group members and membership changes**.

Describe the group's public objective, review its draft and required approvers, and answer public clarification questions. Keep private limits in your own private conversation. Confirm only the exact conditions you reviewed. Permission for an adjustment, permission to disclose exact text and final proposal approval are separate choices; declining one does not authorize another.

Use **Open decision** for an existing decision. **Review saved decision draft** retrieves the saved draft and its recovery path. Check the shared outcome and your private part before approving the exact proposal. A changed roster or outdated action requires refresh and renewed review.

A shared display has separate read-only access to public information. The simulated assistant cannot read private needs or approve for anyone. Use fictional data in the preview; do not infer live acceptance or production readiness from a demo. Hosted signup completion and full current online qualification remain subject to the recorded verification results.

Developer verification: use the pinned Node/npm versions and `npm run check`. Deployment and live qualification are separate workflow results; consult their actual source SHA, actor, usage and CLEAN report before claiming a live pass. Do not duplicate active runs.
