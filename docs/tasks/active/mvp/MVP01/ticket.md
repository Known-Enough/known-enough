3. **Groups and decisions:** new users can request/receive admission, create groups, invite/join, create a new decision and see persisted shared progress from separate sessions. Verify organizer/member/outsider/display views; expired/reused invitations and membership changes must not preserve stale access/confirmations/approvals. 4. **Real AI journey:** shared frame creation and review, private input interpretation and confirmation, queued negotiation/proposal delivery, questions/concessions/disclosures where applicable, and independent approval by every required participant. Approvals must apply to the exact current proposal, not execute a purchase or booking.
5. **Usability:** phone and desktop viewport evidence, clear signup versus sign-in, no duplicated/conflicting screens, understandable next actions, useful progress while AI runs, keyboard/focus/loading/error behavior, readable styles and no overflow. Refreshing or switching devices must recover server progress without another paid job. Distinguish browser viewport tests from actual physical-device tests. Fix essential blockers; defer polish that does not prevent use.
6. **Reliability:** actual API errors, delayed/lost acknowledgments, retries, worker restart/duplicate delivery, network loss, stale results, membership/session changes, concurrency and model failure. Check bounded recovery, accurate progress and no duplicate model charges or stale publication. Inspect available finite server/job/GitHub logs; record missing observability and correct it without logging private input.
7. **Privacy and operations:** server-verified ownership, strict public allowlists, independent consent, current version guards, scoped logs, usage tracking/spending behavior and essential export/deletion/retention requirements.
