Task IDs identify work, not branches. A01/workflow, B01 and B02 are now consolidated; [main integration](main-integration.md) records verification/publication state and safe synchronization for both clones. Never share a writable checkout or synchronized working directory. Keep exactly one active implementation or review task across the project. Use small coherent local commits and keep shared main usable. The user has granted standing authorization to push completed task changes, verified documentation-only updates, and checked reviewable checkpoints explicitly to `origin main`, with no per-push confirmation. Before each push, fetch/inspect the shared head, incorporate incoming changes without discarding local work, resolve conflicts and rerun affected checks. A checkpoint may be pushed for its named reviewer after focused checks; keep its status REVIEW/BLOCKED and downstream tasks gated until the review/acceptance passes. Documentation-only tracking updates may be pushed after documentation checks without changing task acceptance. After pushing, verify `main` and `origin/main` match; the other clone pulls before claiming the next task. If push or sync fails, stop task work and report it rather than leaving an unnoticed local-only commit. Never force-push. Preserve existing task branches; integrate their work without reset/overwrite.

All tasks belong to one shared queue. Either user may take the next task, including frontend, backend, infrastructure, documentation or review work; A/B IDs are historical references, not user assignments. ## Compact logs and handoffs

Each developer writes only their own work log. Update at claim, meaningful change/blocker, checkpoint, transfer and handoff, not after every shell command. Include UTC time, task, actual developer/model/effort, baseline or diff, changed files, result/decision, checks with exit/results, limitations and next action. Link to long test output only when useful; no transcript dumps, secrets or participant data. The ticket owns status/claim; the board summarizes it. Update shared board/handoffs in a coordinated batch; do not turn all records into competing status sources.

Logs in separate clones become visible only after an authorized share or human transfer. This workflow creates no live messaging, locks, cross-account access or background agents. A dated report is not proof of another clone's current state.
