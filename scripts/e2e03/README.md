# E2E03 persistent session runner

This small runner keeps U1 and U2 in separate browser contexts and reuses their live pages. It never exports authentication storage. HTTP evidence contains normalized paths/statuses, never bodies, headers or query strings. Each command persists an intent before dispatch and a result afterward; failures attempt a masked screenshot while the page is still open. Raw inspection/error files and fixture mapping stay in the separate private directory.

From the repository, prepare a new run using `node scripts/e2e03/session-runner.mjs --prepare --evidence docs/review-artifacts/E2E03/<UTC>`. Publish that startup checkpoint before opening a browser. Then run with `--serve --evidence <same-directory> --credentials <private-file> --private-dir <private-directory> --dependencies <checkout-with-node_modules>`.

Use the repository's Node 24.21.0 runtime (Playwright requires Node 20 or newer). The process accepts one JSON command per input line, for example `{"actor":"U1","operation":"login"}`. Await each result before the next command. Complete U1/U2 login and `reconcile` before `open-group` or any form writes. `inspect` saves a private control inventory. `fill-draft` only edits the form; `save-draft` makes one explicit save. `close` shuts down the browser and input reader. No command is automatically retried. After failure, dependent commands are skipped; only inspection or an explicit read-only `refresh` may proceed. Resume uncertain writes by read-only inspection, never by repeating them.

Account/groups HTTP failures now end the login wait immediately and retain their status, normalized route and allowlisted server reference/code. They are classified as APP_HTTP separately from browser/controller timeouts. Screenshots are masked and capped at two; the first failure remains in the summary even when a later prerequisite also fails. These final changes were saved after the user stopped testing and have not been rerun.

Run the bounded regression checks with `node --test scripts/e2e03/session-runner.test.mjs`. They cover the actual Playwright Response shape, identifier-safe networking evidence, and timeout evidence persisted before page closure. The 2026-10-19 timeout's confirmed cause was calling nonexistent `response.method()` inside a catch-all predicate that always returned false. This harness fixes the predicate without changing the app or AWS.

Decision creation/opening now waits for the acknowledged decision ID on the open dialog and its exact expected heading. The loading shell also uses `open-decision-title`, so heading visibility alone is insufficient. A bounded failure reports `DECISION_VIEW_NOT_READY` without repeating creation. The five focused checks include a local Chromium fixture for loading/wrong-record/wrong-title states; Chromium must be installed. This fixture makes no site or account requests. Before another live run, reconcile the existing acknowledged draft/decision from the previous private fixture mapping; do not create a replacement.
